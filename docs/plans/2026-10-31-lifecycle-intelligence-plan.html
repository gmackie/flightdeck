Lifecycle intelligence: 12-PR delivery plan Draft for workshop

2026-10-31 · gmackie/flightdeck · branch docs/lifecycle-intelligence-rfc · issue FLIG-17 · targets main only

Recommendation. Land the contracts first (schema vocabulary and authorization), then the engine adapter, registry and ingest. The read model waits for a passing cross-branch contract test. Nothing is released until gates G1–G8 are green. The design is in the RFC; this page is the implementation order.
Integration gate. The current work-in-progress contracts of workstreams A (events, FLIG-19) and B (engine, FLIG-16) are not compatible: case.created/case.started vs case.start, stage.entered vs stage.enter, event.corrected vs supersedes, among others. G1 (one vocabulary) and G2 (cross-branch contract test) must pass before PR-07 merges and before any feature release.

Overview

Twelve PRs deliver process intelligence for any lifecycle (hiring, deployments, incidents, …) on top of the existing Flightdeck Worker. Four of them continue work already in flight (A, B, C, E); the rest are new follow-ups. Old stacked drafts #1–#18 are not merged; their reusable concepts are listed in Appendix A.

Goals and non-goals

GoalsNon-goals
One wire vocabulary; idempotent, server-only lifecycle ingest; deterministic fold; D1 read model rebuildable from Iceberg; an API with freshness, sample and comparability in every response; scoped reads with suppression; a read-only MCP; accessible segmented barsA workflow engine; people analytics or actor identities; causal claims, simulation or experiments; changes to existing events/sessions/live/trends behavior; merging the old feat/* stack
